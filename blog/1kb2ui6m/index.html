一、它是什么

正则表达式（regex）是一台从文本里找出位置的机器。你写下一个"形状"，引擎拿着它在字符串上滑动，回答两个问题：有没有、在哪里。

所以它本质上只做一件事——匹配（match）。替换、提取、校验、切分都是在"匹配到位置"之后由宿主语言附加的动作。理解这一点，才不会写出"用正则解析 HTML 嵌套标签"这类注定失败的东西。

三个层次的记忆结构

  • 原子：单个字符或字符类，描述"一个位置应该长什么样"；
  • 量词：接在原子后面，描述"重复几次"；
  • 位置断言：^ $ \b 不消耗字符，只描述"这个位置必须满足的条件"。

复杂正则看起来吓人，拆开永远是这三样的组合。

引擎的两大流派

这是全文最重要的一张表。同一条正则放在不同工具里行为不同，绝大多数"网上抄来跑不通"都是因为这个。

流派匹配方式支持功能代表实现
DFA / 自动机文本主导，一次扫过只有基础语法，不支持反向引用、捕获组的回溯语义grep -E、awk、sed、Go regexp、RE2、ripgrep 默认
回溯（backtracking）模式主导，深度优先试错功能齐全：反向引用、环视、惰性量词、原子组PCRE/PCRE2、Perl、Python re、Java、JavaScript

回溯引擎功能强但可能指数级变慢（见第九节）；自动机引擎线性时间但功能受限。同一门语言里可能同时有两者——Go 的 regexp 是 RE2，Python 的 re 是回溯，这就是为什么 Python 里的 (a+)+$ 能打死进程，而 Go 不会。

# 自动机引擎：不支持 \d 简写，要用 POSIX 类
echo 'a1' | grep -E '[[:digit:]]'      # ✅ 匹配
echo 'a1' | grep -E '\d'               # ⚠️ 多数 grep 里 \d 是字面 "d" 或报错
# 回溯引擎：支持 \d、环视、惰性
echo 'a1' | perl -ne 'print if /\d/'   # ✅ 匹配
# Python 里 \d 有效；但 \p{...} 默认无效
python3 -c "import re; print(re.search(r'\d','a1'))"

正则的语法家族

语法谁在用特点
BRE（基本正则）grep 默认、sed 默认元字符要加反斜杠才生效：\( \) \{ \+ | \?
ERE（扩展正则）grep -E、sed -E / -r、awk`(){}
PCREPerl、PHP、Python（近似）、grep -P、nginx、几乎所有语言库ERE 超集 + 环视、反向引用、惰性、命名组、Unicode 属性
RE2Go、rust regex、ripgrep 默认模式PCRE 的受限子集，明确不支持环视与反向引用

警告

BRE 与 ERE 的陷阱：符号含义会翻转 在 BRE 里 \+ 是"一次或多次"，而在 ERE 里 \+ 是字面加号。反过来 + 在 BRE 里是字面字符。

echo 'aaa' | grep 'a\+'      # ✅ BRE：匹配
echo 'aaa' | grep -E 'a\+'   # ❌ ERE：匹配字面 "a+"，无输出
echo 'a+'  | grep -E 'a\+'   # ✅ ERE：这才是它的用法

看到一条正则先问自己：这是给哪套语法写的？ 把 PCRE 正则直接丢给 grep 是最常见的翻车点。

二、最常用：字符类与简写

按使用频率从高到低。通用性一列标出只有回溯引擎才有的写法。

1. 高频简写

写法含义等价展开通用性
.任意单个字符（默认不匹配换行）—通用
\w单词字符[A-Za-z0-9_]PCRE + Python/JS/Java；POSIX 工具需用 [[:alnum:]_]
\W非单词字符[^A-Za-z0-9_]同上
\d数字[0-9]PCRE + Python/JS/Java；POSIX 用 [[:digit:]]
\D非数字[^0-9]同上
\s空白（空格 / Tab / 换行 / 换页等）[ \t\n\r\f\v]PCRE + Python/JS/Java；POSIX 用 [[:space:]]
\S非空白[^ \t\n\r\f\v]同上
\h水平空白（空格 / Tab，不含换行）[ \t]PCRE、Perl 5.10+；Java 是 \h 十六进制字符，含义完全不同
\v垂直空白[\n\r\f\x0b]PCRE、Perl 5.10+；JS 里 \v 是单个垂直制表符
\R任意换行序列（含 \r\n）`(?>\r\n\n

\d 在 Unicode 模式下不是 [0-9]

Python 3 的 \d、\w、\s 默认匹配 Unicode 字符——\d 能匹配阿拉伯-印度数字 ٣，\w 能匹配中文。想要 ASCII 语义，写 re.ASCII 标志或显式用 [0-9]。

import re
print(re.search(r'\w', '中'))                  # 匹配到
print(re.search(r'\w', '中', re.ASCII))        # None

2. 自建字符类

写法含义示例
[abc]a、b、c 任一gr[ae]y 匹配 gray / grey
[^abc]除 a、b、c 之外任一字符[^0-9] 非数字
[a-z]区间[a-zA-Z0-9] 字母数字
[a-zA-Z0-9_]组合区间，中划线前后必须有序写 [z-a] 在很多引擎里直接报错
[-a] / [a-]中划线在开头或结尾是字面[-+] 匹配减号或加号
[]a]] 放开头是字面有些引擎要求 [\]]，PCRE 也接受 []a]
[\d\s]类内可混用简写PCRE / Python
[\w-[aeiou]]类内差集.NET、Java 支持；PCRE 不支持
# 十六进制色值
echo '#a3f' | grep -E '^#[0-9a-fA-F]{3}$'

提示

. 为什么不匹配换行 历史原因：早期工具按行处理，. 就是"这一行里的任意字符"。POSIX 里叫 REG_NEWLINE，PCRE 用 s（DOTALL）标志改变它。

printf 'a\nb\n' | perl -0777 -ne 'print "matched\n" if /a.b/s'   # s 让它跨行
printf 'a\nb\n' | perl -0777 -ne 'print "matched\n" if /a.b/'    # 默认不跨行

想要"匹配任意字符包括换行"又不想用标志，可以用 [\s\S]（所有引擎通用）：[\s\S]* 是跨行匹配的万能写法。

3. POSIX 字符类（自动机引擎唯一的选择）

grep、awk、sed 只认这套，必须写在方括号里：[[:digit:]]。

类等价说明
[[:alpha:]][A-Za-z]字母（受 locale 影响）
[[:digit:]][0-9]数字
[[:alnum:]][A-Za-z0-9]字母 + 数字
[[:upper:]] [[:lower:]]—大写 / 小写
[[:space:]][ \t\r\n\v\f]空白
[[:blank:]][ \t]只含空格和 Tab，不含换行
[[:punct:]]—标点符号
[[:xdigit:]][0-9A-Fa-f]十六进制数字
[[:cntrl:]]—控制字符
[[:print:]] [[:graph:]]—可打印（前者含空格） / 可见字符
[[:word:]][A-Za-z0-9_]GNU 扩展，POSIX 未定义
# 注意：POSIX 类写在括号里，外面还可以再套区间组合
grep -E '^[[:alpha:]][[:alnum:]_]*$' names.txt

注意

[[:alpha:]] 在 UTF-8 locale 下能匹配中文 因为 [:alpha:] 语义由 locale 决定。想让 grep 按字节走老行为，设 LC_ALL=C。这条同时影响 sed、awk 的字符类，也让"同一个正则在不同机器上结果不同"——排查时先 locale 看一眼。

三、位置断言（零宽）

零宽意思是它不消耗字符，只声明"此处必须满足条件"。所以 ^^^abc 和 ^abc 等价。

写法含义通用性
^行/串开头通用
$行/串结尾通用
\A串开头（不受多行标志影响）PCRE、Python、Java；JS 无
\Z串结尾（允许结尾有换行）PCRE、Python；Java 的 \Z 是绝对结尾
\z绝对串结尾（不允许尾部换行）PCRE、Java、Python（3.14+）；Python 旧版无
\b单词边界通用（ERE 也支持）
\B非单词边界通用
\< \>词首 / 词尾GNU 扩展：GNU grep/sed/awk 有；BSD sed 不认 \<，要用 [[:<:]]；Perl/PCRE 无
\G上一次匹配结束的位置PCRE、Perl、Java
# ^ $ \b 三个的差别
printf 'foo bar\n' | grep -E '\bbar'      # 词首边界 → 匹配
printf 'foo bar\n' | grep -E 'bar\b'      # 词尾边界 → 匹配
printf 'foobar\n' | grep -E '\bbar'       # 无边界 → 不匹配
printf 'foobar\n' | grep -E '\Bbar'       # 非边界 → 匹配

注意

\b 不是 POSIX 标准，BSD 与 GNU 分道扬镳 GNU 的 grep/sed/awk 把 \b 当单词边界（并额外提供 \< \>），BSD/macOS 的 sed 两个都不认，写成 s/\bbar/X/ 会静默失败、什么都不替换。

# GNU sed：两种都能用
printf 'foo bar\n' | sed 's/\bbar/X/'
printf 'foo bar\n' | sed 's/\<bar/X/'
# BSD sed：必须用 [[:<:]] / [[:>:]]，且 GNU grep 不认这对
printf 'foo bar\n' | sed 's/[[:<:]]bar/X/'

要写跨平台脚本，索性避开词边界——用取反类自己描述上下文，比如把"独立的 bar"写成 (^|[^[:alnum:]_])bar([^[:alnum:]_]|$)；或者直接用 perl/awk 处理。

$ 到底是不是"字符串结尾"

多数引擎默认 $ 匹配字符串结尾，也可以匹配结尾处的前一个换行。开了多行标志（m / MULTILINE）后，$ 匹配每一行的结尾。

Perl 的 $ 还有"允许结尾换行"的宽松行为："abc\n" =~ /abc$/ 在 Perl 里匹配成功。想严格到末尾就用 \z。Python 的 re 有完全相同的行为（$ 允许一个尾部 \n，\Z 也是），这是常见误解的来源。

# 用 Perl 看差别
printf 'abc\n' | perl -ne 'print "dollar: matched\n" if /abc$/'
printf 'abc\n' | perl -ne 'print "\\z: matched\n" if /abc\z/'
printf 'abc\n' | perl -0777 -ne 'print "\\Z: matched\n" if /abc\Z/'

环视（lookaround）

零宽断言的进阶形态，只有回溯引擎支持。RE2 / Go / ripgrep 默认模式全都不支持，遇到 (?= 会直接报错。

写法名字含义
(?=...)正向前瞻右边是这个
(?!...)负向前瞻右边不是这个
(?<=...)正向后顾左边是这个
(?<!...)负向后顾左边不是这个
# 提取 "价格:" 后面紧跟的数字，但不把 "价格:" 本身吃进去
echo '价格:199' | perl -ne 'print "$1\n" if /(?<=价格:)(\d+)/'

# 匹配不含 "cat" 这个单词的内容（负向前瞻 + 捕获组）
# 注意 (?!cat\b) 里的 \b 不能省：只写 (?!cat) 会让 catalog 也被排除
echo 'dog cat bird' | perl -ne 'print "$1 " while /\b(?!cat\b)(\w+)\b/g'
# 输出: dog bird

# 密码规则：至少一位数字、一位大写，长度 ≥ 8（多个前瞻叠加）
echo 'Abcdefg1' | perl -ne 'print "ok\n" if /^(?=.*\d)(?=.*[A-Z]).{8,}$/'

警告

后顾的长度必须固定(?<=\w+) 在大多数引擎里非法，因为 \w+ 长度不定。PCRE 和 Java 支持"有限长度"的后顾（(?<=\d{1,3})），而 Python 从 3.12 起支持变长后顾，更早的版本只允许固定长度。跨引擎时，把变长后顾改写成"捕获组 + \K 或提取"更稳。

\K 是"丢弃已匹配部分"，效果类似后顾但更好写（PCRE、Perl、grep -P）：

echo 'user:alice' | perl -ne 'print "$&\n" if /user:\K\w+/'

四、量词（重复次数）

写法含义通用性
*0 次或多次通用
+1 次或多次通用（BRE 要写 \+）
?0 次或 1 次通用（BRE 要写 \?）
*? +? ??惰性：尽量少匹配回溯引擎
*+ ++ ?+占有：不回溯PCRE、Perl、Java
{n}恰好 n 次通用（BRE 要写 \{n\}）
{n,}至少 n 次同上
{n,m}n 到 m 次同上
{,m}至多 m 次PCRE 2 支持；多数引擎不认，写 {0,m} 最稳

贪婪 vs 惰性 vs 占有：一次讲清

引擎默认贪婪——能吃多少吃多少，然后为了整体匹配成功而回溯。

$ echo '<a><b>' | perl -ne 'print "$1\n" if /<(.*)>/'
a><b            # 贪婪：.* 吃掉到最后一个 >
$ echo '<a><b>' | perl -ne 'print "$1\n" if /<(.*?)>/'
a               # 惰性：够用就停

惰性不是"更快"，只是换了个搜索方向。真正的性能工具是占有量词和原子组——它们禁止回溯：

# 占有量词 a++ 与原子组 (?>a+) 语义等价
$ perl -e '"aaab" =~ /(?>a+)b/ and print "matched: $&\n"'
matched: aaab
# 原子组能防止灾难性回溯
$ time perl -e '"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaa!" =~ /^(a+)+$/; print "done\n"'
done            # 立刻返回

提示

.* 与 [^x]* 的取舍 当你明确知道"不能跨越某个字符"时，用取反类比 .*? 更安全也更快：

# 提取两条竖线之间的内容——用 [^|]* 而非 .*?
echo 'a|hello|b' | perl -ne 'print "$1\n" if /\|([^|]*)\|/'

[^|]* 是确定性的，引擎不需要试错；.*? 会让引擎反复回溯试探。

五、分组、捕获与引用

写法名字说明
(...)捕获组产生 \1、$1，也是量词的作用范围
(?:...)非捕获组只分组不捕获，省内存，语义更清晰的写法
(?<name>...) / (?P<name>...)命名捕获组Perl/PCRE (?<n>)；Python/旧版 PCRE (?P<n>)
\1 \2反向引用引用前面捕获组匹配到的文本，不是模式
\g{1} \g{-1}反向引用（明确写法）PCRE / Perl，\g{-1} 表示"上一个组"
\k<name> / (?P=name)命名反向引用PCRE \k<n>；Python (?P=n)
`(?...)`分支重置
(?>...)原子组内部不允许回溯
(?#...)注释多数引擎支持；(?#) 里的内容被忽略
`(?(1)yesno)`条件匹配
`(?(?=...)yesno)`条件匹配（断言形式）
# 反向引用校验重复：找出连续重复的单词
$ echo 'the the cat' | perl -ne 'print "重复: $1\n" if /\b(\w+)\s+\1\b/'

# 匹配成对标签（注意：只适用于不嵌套的场景）
$ echo '<b>hi</b>' | perl -ne 'print "$&\n" if m{<(\w+)>.*?</\1>}'

# 命名组可读性更好
$ echo '2024-05-01' | perl -ne '/\d{4}-(?<m>\d{2})-(?<d>\d{2})/ and print "$+{m}/$+{d}\n"'

反向引用在自动机引擎里没有

grep -E '(a)\1' 在 GNU grep 里能用（GNU 的实现比严格 ERE 宽松），但 Go 的 regexp、RE2、ripgrep 默认模式会直接报错 invalid escape sequence。写"到处能跑"的正则，就别用反向引用。

捕获组的编号规则

  1. 按 ( 出现的顺序从左到右编号，从 1 开始；
  2. (?:、(?=、(?!、(?<= 等不参与编号；
  3. 命名组同时占用编号，所以 (?<a>..)(?<b>..) 里 $1 和 $+{a} 是同一个；
  4. 嵌套时外层先编号：((a)(b)) 中 $1 是整体，$2 是 a，$3 是 b。
# 用 sed 提取，验证编号
$ echo 'user=alice;id=42' | sed -E 's/.*user=([^;]+);id=([0-9]+).*/\1 \2/'
alice 42

六、分支与优先级

| 的优先级低于拼接，所以 ^ab|cd$ 是 (^ab)|(cd$)，不是 ^(ab|cd)$。这是新手最常写错的一处。

$ printf 'ab\nabcd\n' | grep -E '^ab|cd$'   # ab 行、abcd 行都匹配
ab
abcd
$ printf 'ab\nabcd\n' | grep -E '^(ab|cd)$' # 只有 ab
ab

分支是"短路"的

foo|foobar 在遇到 foobar 时只匹配 foo——引擎按书写顺序试，第一个成功就停。所以长分支要写在前面，或干脆用 foobar|foo。

$ echo 'foobar' | perl -ne 'print "取出: $&\n" if /foo|foobar/'
取出: foo

优先级从高到低（记住这个顺序就能自己推断）：

1. 转义序列      \d  \.  \n
2. 字符类        [abc]
3. 分组          (...)
4. 量词          * + ? {n,m}
5. 拼接          abc
6. 分支          a|b

七、修饰符 / 标志

标志（flag）控制"匹配方式"，不改变模式本身。

标志（各语言名）作用通用性
i / IGNORECASE / (?i)忽略大小写通用
m / MULTILINE^ $ 匹配每行首尾通用
s / DOTALL. 匹配换行通用
x / VERBOSE / (?x)忽略空白与 # 注释，可多行书写正则PCRE、Python；JS 无
u / UNICODEUnicode 模式（影响 \w \d \b）Python re.UNICODE、JS u
U / UNGREEDY量词默认反转成惰性PCRE、Perl
g全局匹配（找所有，不返回第一个就停）JS / Perl s///g / grep -o
a / ASCII强制 ASCII 语义Python
A / ANCHORED强制从串首开始PCRE、Python
J允许同名捕获组Python 3.11+ 才有
# 行内标志：写在 (?...) 里，作用范围到模式末尾（或到 (?-i) 为止）
$ echo 'ABC' | perl -ne 'print "ok\n" if /(?i)abc/'
$ echo 'abc' | perl -ne 'print "ok\n" if /(?i:abc)/ and 0'

# 只在局部生效
$ perl -e 'print "ok\n" if "aBc" =~ /a(?i:b)c/'
# 分隔符：Perl 允许换成任意配对符号，省得到处转义斜杠
$ echo '/usr/local/bin' | perl -ne 'print "$1\n" if m{/usr/(\w+)}'
local

提示

x 标志是写长正则的正道 把复杂正则折行书写，带缩进和注释，可读性提升巨大。写完后各语言都能开启 VERBOSE 模式运行。

import re
pattern = re.compile(r"""
    ^                   # 串首
    (?P<scheme>https?)  # 协议
    ://
    (?P<host>[^/\s]+)   # 主机（不含斜杠和空白）
    (?P<path>/[^\s]*)?  # 可选路径
    $
""", re.VERBOSE)

八、转义规则

哪些字符需要转义取决于它在上下文中有没有特殊含义。

上下文需要转义的字符
类外（PCRE/ERE）. * + ? ( ) [ ] { } ^ $ |
类外（BRE）. * [ ] ^ $ \ 是特殊；+ ? ( ) { } | 需加反斜杠才特殊
类内] \ ^ -（^ 仅在首位特殊，- 仅在两个字符之间特殊）
换行/控制字符\n \t \r \f \v，或 \xHH（十六进制）、\0（NUL）
Unicode 码点\u4e2d（多数引擎）、\x{4e2d}（PCRE/Perl）、\N{U+4E2D}（Perl）

三层转义：最耗调试时间的地方

一行命令里往往有 shell → 工具 → 正则 三层，反斜杠被反复解释。

# 想匹配字面反斜杠
echo 'a\b' | grep -F 'a\b'            # 最省事：-F 关闭正则
echo 'a\b' | grep 'a\\b'              # 正则里 \\ 表示一个字面反斜杠

# 想匹配字面 "d"（而不是 \d）
echo 'a\d' | grep -E '\\d'

# shell 双引号里，$ 和 \ 都会被 shell 先处理
echo '$1' | grep '\$1'                # 单引号安全
echo '$1' | grep "\$1"                # 双引号也行，因为 \$ 转义了

对策按优先级：① 尽量用单引号包裹 → ② 能用 -F 的固定字符串就别用正则 → ③ 在脚本文件里写正则，避免 shell 层。

# 需要匹配单引号本身时：'"'"' 或退出单引号
echo "it's" | grep "it's"

九、性能与常见陷阱

1. 灾难性回溯

(a+)+$ 这类"嵌套量词 + 可失败后缀"会让回溯引擎尝试指数级组合。构造输入把一个正常的正则变成 CPU 炸弹。

危险模式问题修法
(a+)+嵌套量词，同一串有多种切分方式a+ 或 (?>a+)
(a|a)+分支重叠合并成 a+
(.*),(.*) 长文本两个 .* 互相回溯改成 [^,]*,[^,]*
([\w]+)*嵌套量词\w+
^\s*.*\s*$多个可匹配空串的量词相邻明确边界
# 演示：1 秒内返回说明没炸；29 个 a 已经能让多数引擎卡住
$ time perl -e '"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaa!" =~ /^(a+)+$/; print "done\n"'
done

2. 其它高频陷阱

陷阱说明对策
用正则解析 HTML/JSON嵌套结构正则表达不了用 HTML::TreeBuilder、jq、专用解析器
^ $ 被当成"字符串首尾"多行数据里误解明确是否开 m 标志
忘了 g / -o只拿到第一个匹配grep -o、preg_match_all、/g
[.-z] 意外成区间. 在类内被当区间端点转义或移到首尾：[-.z]
大小写与 locale[a-z] 在不同 locale 下范围不同明确写 [a-zA-Z] 或设 LC_ALL=C
中文字符按字节数. 匹配的是字符还是字节取决于模式Python 用 str 而非 bytes；Perl 加 use utf8
惰性量词不生效后面没有能让引擎停下的约束惰性需要"右侧锚点"；配合 \b $ 等
反向引用找的是文本(a)\1 匹配 "aa" 而非 "a" 后跟任意想复用模式用 \g 或重写

注意

"看起来能用"的正则最危险 只在自己造的一两条样例上测过就上线，遇到边界输入才暴雷。至少测三类输入：空串、最短合法输入、故意构造的畸形输入。

# 用多行样例一次性验证
printf '\n\na@b.com\nbad@\n@x.com\n' | grep -E '^[^@[:space:]]+@[^@[:space:]]+\.[[:alpha:]]{2,}$'

十、实战配方（可直接抄）

1. 校验类

# 邮箱（务实版，不要追求"完全符合 RFC"——那正则没人看得懂也照样出错）
grep -E '^[^@[:space:]]+@[^@[:space:]]+\.[[:alpha:]]{2,}$' emails.txt

# IPv4（逐段限定 0-255，写法冗长但准确）
grep -E '^((25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])\.){3}(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])$' ips.txt

# 日期 YYYY-MM-DD（含粗略范围校验）
grep -E '^[0-9]{4}-(0[1-9]|1[0-2])-(0[1-9]|[12][0-9]|3[01])$' dates.txt

# 时间 HH:MM:SS
grep -E '^([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9]$' times.txt

# 手机号（中国大陆，1 开头第二位 3-9）
grep -E '^1[3-9][0-9]{9}$' phones.txt

# 强密码：8 位以上，含大小写、数字、特殊字符
perl -ne 'print if /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[^\w\s]).{8,}$/'

2. 提取类

# 提取引号内内容（成对、不跨行）
grep -oE '"[^"]*"' config.txt

# 提取 URL 的各个组成部分
echo 'https://example.com:8443/path/to?a=1&b=2' | \
  perl -ne 'print "$1|$2|$3|$4\n" if m{^(\w+)://([^/:]+)(?::(\d+))?(/[^?\s]*)?}'

# 提取 Markdown 链接
grep -oE '\[[^]]+\]\([^)]+\)' doc.md

# 提取日志级别、时间、消息
printf '2024-05-01T10:00:00Z ERROR 磁盘满了\n' | perl -ne '/^(?<ts>\S+)\s+(?<lvl>\w+)\s+(?<msg>.*)$/ and print "$+{lvl}: $+{msg}\n"'

# 只取每行最后一个字段（不给 awk 也行）
sed -E 's/.*[[:space:]]//'

# 取两个标记之间的内容（非贪婪）
perl -ne 'if (/BEGIN(.*?)END/) { print "$1\n" }' file.txt

3. 替换类

# 批量重命名（配合 shell 循环）
for f in *.txt; do echo mv "$f" "$(echo "$f" | sed -E 's/^([0-9]+)_/\1-/')"; done

# 去掉行尾空白
sed -E 's/[[:space:]]+$//' file.txt

# 千分位分隔：把"后面刚好是 3 的倍数个数字"的空隙替换成逗号
echo '1234567' | perl -pe 's/(?<=\d)(?=(\d{3})+(?!\d))/,/g'      # → 1,234,567

# 驼峰转下划线
echo 'myVariableName' | sed -E 's/([a-z0-9])([A-Z])/\1_\2/g' | tr 'A-Z' 'a-z'

# 引号统一：单引号转双引号
# 坑点：shell 双引号里的 \" 会先被 shell 吃掉，正则里就只剩一个孤立引号
#       正确做法是用 Perl 的花括号定界 + \$1，让 shell 不参与解释
echo "key='value' other='x'" | perl -pe "s{'([^']*)'}{\"\$1\"}g"      # → key="value" other="x"

# sed 同样的问题：不要在双引号里写 '，改用字符类 ['] 绕开
echo "key='value' other='x'" | sed -E "s/[']([^']*)[']/\"\1\"/g"

# 多数场景其实只想删掉引号，那 tr 最直白
echo "key='value' other='x'" | tr -d "'"

# 删除注释行与空行
grep -vE '^[[:space:]]*(#|$)' config.txt

4. 复杂组合

# 匹配不包含某词的整行（负向前瞻）
grep -P '^(?!.*(TODO|FIXME)).*$' src.txt      # 需要 PCRE 版 grep

# 用 awk 实现同样的效果（不需要 -P）
awk '!/TODO|FIXME/' src.txt

# 匹配 log 中 5xx 状态码且耗时超过 1 秒
awk '$9 ~ /^5[0-9][0-9]$/ && $NF > 1000000' access.log

# 反向引用去重：找出连续三行完全相同的内容
perl -ne 'push @l, $_; if (@l > 2) { shift @l; print "$l[0]" if $l[0] eq $l[1] && $l[1] eq $l[2] }' file.txt

# 多模式一次扫描（把正则放进变量，用 | 拼接）
patterns='error|warn|fatal'
grep -iE "$patterns" app.log

# 括号配对：这条能覆盖"两层嵌套"，可再套第三层就匹配不到了
echo '(a(b)c)' | grep -E '\([^()]*\([^()]*\)[^()]*\)'    # ✅ 输出 (a(b)c)
echo '(a(b(c))d)' | grep -E '\([^()]*\([^()]*\)[^()]*\)' # ❌ 三层嵌套无输出
# 真需要任意层嵌套时换工具
python3 -c "
import sys, re
s = sys.stdin.read()
depth = 0
for i, ch in enumerate(s):
    depth += (ch == '(') - (ch == ')')
    if depth == 0 and ch == ')':
        print(s[:i+1]); break
" <<< '(a(b(c))d)'

提示

正则变量要用 -e 或引号保护 模式来自 shell 变量时，如果它可能以 - 开头，用 grep -e "$pattern"。变量里含空格或 | 时，记得仍要引号包裹，否则会被 shell 拆成多个参数。

pattern='^-[0-9]+$'
grep -e "$pattern" file.txt

同一件事在不同命令里的写法：

目的grepsedawkperl

别把 PCRE 正则丢给 grep

\d、(?=)、(?:)、\b（部分版本）、惰性 .*? 在 POSIX 工具里都不保证可用。判断办法：先用一行样本试跑，看报错还是静默不匹配。

# 一个"能看出问题"的探针
echo 'a1' | grep -E '\d' && echo "支持 \\d" || echo "不支持 \\d"
echo 'abc' | grep -E '(?:a)bc' >/dev/null 2>&1 && echo "支持 (?:)" || echo "不支持 (?:)"

十二、调试方法

正则是声明式的，没法加断点，只能靠"分而治之"。

方法做法
二分法把模式从中间拆开，分别验证左右两半哪个错了
锚点法临时加 ^ $，把"匹配到子串"变成"匹配整串"，暴露多余的部分
-o 可视化grep -oE 或 Perl 的 $& 打印实际匹配到的文本，常能一眼看出多吃了什么
-x / \A...\z强制整行匹配，排除隐藏字符干扰
十六进制看一眼cat -A、hexdump -C，确认行尾是 \n 还是 \r\n、有没有 BOM
x 标志把冗长的正则折行加注释，错误往往在书写过程中就暴露了
在线工具regex101 支持分步调试（选对 flavor 很重要）
# 最实用的调试三连
printf '%s\n' "$line" | cat -A                # 看隐藏字符和行尾
printf '%s\n' "$line" | grep -oE "$pattern"   # 看匹配到了什么
printf '%s\n' "$line" | grep -xE "$pattern"   # 看能否整行匹配

提示

先问"该不该用正则" 正则擅长无嵌套的线性文本：日志、配置、单行记录、格式校验。

不该用正则的场景：

  • 有嵌套结构 → HTML/XML/JSON 用解析器，jq、xmllint、python -c 'import html.parser'
  • 需要算术或聚合 → awk 或 Python
  • 需要列对齐的表格 → 直接按分隔符切（cut、awk -F）
  • 逻辑超过一屏 → 写成脚本函数，别硬塞进一条正则

一条好正则的长度上限大约是"能在一屏内读懂"。超过了就该拆成"粗筛 + 精处理"两步。

把最该背下来的集中在这里。加粗的是每天都用的。

用法补充
  • 加粗项在 POSIX 工具里要换成等价写法：\d→[[:digit:]]，\w→[[:alnum:]_]，\s→[[:space:]]。
  • \K、(?:)、惰性、环视、原子组只有回溯引擎支持，grep -E / awk / sed 里不要写。
  • BRE 环境下 + ? | ( ) { } 要加反斜杠才具备特殊含义，而 + ? { } 不加反斜杠就是字面字符。

学习路径建议

按这个顺序练，两天能覆盖绝大部分日常需求：

  1. 当天：\d \w \s、.、* + ?、[ ]、^ $、( ) | —— 这九个能解决八成问题；
  2. 第二天：\b、{n,m}、[^ ]、惰性 .*? —— 让匹配变精确；
  3. 之后按需：环视、反向引用、命名组 —— 只在确实需要时学，它们也是各引擎差异最大的部分。

遇到具体问题时的顺序永远是：先判断是哪套语法 → 再用最简单的写法实现 → 最后才考虑优化。把正则写得让人看得懂，比写得短更重要。
